# 내면의 서재 — 다중 출처·자료 유형 콘텐츠 모델

## 목적
내면의 서재는 특정 강연자 전용 페이지가 아니라 여러 강연·책·연구·글을 연결하는 개인 학습 공간이다. 현재 등록 강의 7편은 기존 소유자의 학습 자산으로 유지한다. 향후 새 항목을 **실제 원문을 확보한 뒤** 별도 유형으로 추가한다.

## 자료 등록 계약
### 영상 강의 — `lectures.json`
- 필수: `id`(안정적인 내부 콘텐츠 ID; 검증된 YouTube 영상 ID 또는 별도 슬러그), `kind: "lecture"`, `creator`(실제 화자), `title`, `duration`, `description`, `tags`.
- 날짜는 확인된 공개일만 `date`로 기록하고, `filter_tag`는 필요할 때만 사용한다.

### 책·연구·글·개인 노트 — `materials.json`
현재 값은 `[]`로 시작한다. 새로운 자료가 있을 때만 등록한다.

| 필드 | 설명 |
|---|---|
| `id` | 전체 자료를 통틀어 중복되지 않는 안정적인 식별자 |
| `kind` | `book` · `paper` · `article` · `note` |
| `creator` | 책 저자, 연구자, 글쓴이 등 실제 출처 |
| `title` | 자료 제목 |
| `description` | 학습 자료의 핵심 설명 |
| `tags` | 주제 태그 배열 |
| `url` | 실제 작성 완료된 **사이트 내부 상대경로**. 예: `books/sample.html` |
| `featured` | 선택값. `true`인 자료 한 개를 홈 대표 자료로 강조 |

등록하기 전에 실제 내부 HTML 문서를 생성하고 출처 및 링크를 확인한다. URL은 절대 URL·상위 디렉터리 이탈을 허용하지 않는다. 기존 강의처럼 모든 자료에 동영상 타임라인이나 핵심 요약을 강제하지 않는다. 자료 유형별로 적절한 독서 노트, 논문 분석, 미니강좌 등의 서식을 선택한다.

## 사용자 경험과 운영 규칙
- 자료 카드에는 실제 출처를 표시하며 검색은 제목·설명·강연자/저자·주제 태그를 모두 대상으로 한다.
- 강의별 학습/복습 기록은 기존 동영상 ID를 그대로 유지한다. 향후 책·연구 진행률이 필요하면 **자료 유형을 구분하는 새 저장 경로와 데이터 마이그레이션 계획**을 별도 검토한다.
- 신규 자료/브랜드 변경 후 `scripts/build_library.py`, `scripts/validate_site.py`, 생성기 --check 및 Python/Node/Chromium 검사를 통과시킨다.
- 새 콘텐츠는 사실상 작성 완료한 내부 페이지가 있어야만 등록하며 존재하지 않는 책·논문을 예시 카드로 게시하지 않는다.

## 강연자별 편집 기준
김주환 교수의 내면소통 강의에 적용하던 자막/용어 스타일은 **해당 강의의 편집 규칙**이다. 허버먼의 강의에는 해당 강의의 영어 원본과 학술 자료, 다른 저자의 책에는 저작권과 인용·판본 정보가 기준이다. 서로 다른 원문의 주장을 한 강연자의 주장으로 합치지 않는다.

## 공개 학습 기록 기능 제거 (2026-11-02 · 현행 우선 규칙)
- 스터디 앱은 **로그인 없는 읽기 전용 학습 자료 사이트**로 운영한다. 상단 메뉴는 자료 모음 / 용어와 개념 두 가지다.
- 강의·미니강좌·5분 요약과 댓글 복사, 검색·필터, 화면 버전 안내는 보존한다. **완료·복습 체크, 개인 기록, 진행 상태, 이력 목록, 로그인·계정 UI 및 클라우드 기록 읽기/쓰기 코드를 재도입하지 않는다.**
- `study-history.html`, `assets/progress.js`, `assets/account.js`, `assets/firebase.js`, `assets/firebase-config.js`는 배포 트리에서 제거한다. 서비스 워커에서도 이력 주소를 사전 캐시하지 않는다.
- 기존 원격 Firebase 서버의 데이터는 사이트 코드 제거와 별개이다. **서버의 기록을 자동 삭제했다고 주장하지 않는다.** 데이터의 완전 삭제는 별도 접근 권한과 절차가 필요하다.
- 새로운 강의를 추가할 때 별도 학습 기록 위젯이나 Firebase 저장 기능을 만들지 않는다. 테스트는 기능 부재와 학습 자료의 검색·읽기·댓글 복사 유지 여부를 검사한다.

## 한 문장 핵심의 단일 원본
- `data/mini_courses.json`의 `lead`만 직접 수정한다. `data/summaries.json`에는 같은 내용을 중복 저장하지 않는다.
- `scripts/content_registry.py`가 두 데이터 소스를 결합하고, 누락된 강의 ID·상충하는 한 문장 핵심을 오류로 처리한다.
- 원본 영상의 실제 URL은 검증된 `video_url`로 기록하며 내부 콘텐츠 ID를 영상 ID로 잘못 가정하지 않는다.
