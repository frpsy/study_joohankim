# 스터디 홈 디자인 계약 (AI·사람 공통)

> **현행 우선 (2026-11-06):** 구성은 AGENTS.md ‘현행 구성’, 시각은 이 문서 끝의 ‘블랙·레드·그레이 / v10’ 절이 아래의 이전 절(녹색 팔레트, 미니멀 모던, 메뉴 2개, 5분 요약·미니강좌 관련 내용)보다 우선한다.

## 0. 기준과 범위
- 최종 기준은 assets/site.css의 :root 토큰과 assets/site.js의 공통 동작이다. 이 문서는 기존 스타일의 설계 의도를 설명한다.
- 현재 강의 페이지는 3단 요약 → 원본 댓글 타임라인, 학습 해설은 별도 미니강좌가 기준이다. 이전 마인드맵/독립 해설 의무 규칙은 현행 컴팩트 페이지에 적용하지 않는다.
- 페이지별 style 태그와 인라인 style 속성, 복제된 전용 복사 핸들러를 만들지 않는다. 새 화면을 추가할 때 같은 컴포넌트를 재사용한다.

## 2. 공통 구성과 반응형
- 모든 페이지: 공통 헤더·본문·푸터, 한 페이지 h1 하나, 44px 이상 터치 대상, 읽기 쉬운 왼쪽 정렬.
- 홈: lectures.json + scripts/build_library.py가 유일한 카드 데이터 원본이며 수동 카드 추가 금지.
- 강의: data/lecture_compact.json + scripts/build_compact_lectures.py; 미니강좌는 data/mini_courses.json, 5분 요약은 data/summaries.json에서 생성한다.
- 모바일 기준 분기점은 780px 이하, 매우 작은 화면 보정은 360px 이하를 유지한다. 좁은 화면은 한 열 본문, 가로 넘침 없이 자연스러운 줄바꿈, 최소 16px 입력 글꼴을 지킨다.
- 본문 코드블록은 pre-wrap / overflow-wrap을 유지하되 댓글 원문의 줄바꿈·시간정보·공백을 복사 과정에서 변경하지 않는다.
- sticky 메뉴·해시 앵커·접힌 영역 열기 동작을 유지한다. 기존 URL 앵커는 삭제하지 않는다.

## 3. 공통 상호작용 계약
- 댓글 복사는 data-copy-target이 가리키는 원문 textContent만 복사한다.
- 성공: 버튼 '복사 완료 ✓', 상태 '복사됨'. 2.2초 후 버튼 원래 이름과 상태 문구가 복원된다.
- 실패: 원문을 선택하고 '텍스트 선택됨' 및 직접 복사 안내를 제공한다.
- 상태는 role=status와 aria-live=polite로 알린다. 복사 버튼은 모바일에서도 폭을 독점하지 않는다.

## 4. AI 변경 절차와 검증 증거
1. AGENTS.md → 편집규칙.md → 이 문서 → 저장소 스킬을 읽고 현행 레이아웃과 데이터 생성 경로를 확인한다.
3. 로컬 검사: python3 scripts/validate_design_system.py; python3 scripts/validate_site.py; python3 -m unittest discover -s tests; node --test tests/*.cjs.
4. PR의 네 가지 항목: 변경 범위 / 영향 기능 / 검증 증거 / 남은 위험. GitHub Actions의 정적·상호작용·반응형 스모크 결과를 확인한다.
5. 브라우저 자동화 검사는 실물 아이폰 Safari 검사의 대체물이 아니다. 검증하지 않은 환경은 미검증으로 기록하고, 배포 링크는 실제 공개 파일 확인 후 공유한다.

## 5. 변경 금지와 예외
- UI 작업 시 강의 텍스트·원자료·영상 시각·원문 댓글·진행 기록을 의도 없이 수정하지 않는다.
- 디자인 토큰 변경은 관련 페이지와 모바일/PC 화면에 대한 영향 분석을 포함해야 한다.
- 과거 레이아웃을 되살리는 변경은 명시적 사용자 요청이 없는 한 금지한다.
- 새 규칙은 기존 규칙과 중복·충돌하지 않는지 확인하고 AGENTS.md, 편집규칙.md, 스킬, 테스트 중 필요한 곳을 함께 갱신한다.

## 6. 한국어 화면 문구
- 간결하고 자연스러운 한국어가 기준. 모든 문장을 ‘~한다/~이다’로 끝내는 획일적 문체 강제 금지.
- 페이지 제목과 중복되는 소개 문구는 과감히 줄이거나 삭제한다. 상태는 ‘아직 기록 없음’, ‘불러오는 중’처럼 바로 이해되게 표현한다.
- 용어 카드에는 정확한 정의와 중요한 구별만 남긴다. UI에는 간결한 명사구, 해설에는 자연스러운 완결문을 적절히 사용한다. 문장 끝을 일괄 치환하지 않는다.
- 학습 콘텐츠의 연구·인과·한계·출처는 스타일을 이유로 삭제하지 않는다. 최신 세부 기준은 편집규칙.md의 ‘한국어 문체와 화면 문구’에 둔다.

## 댓글 타임라인과 화면 버전
- 댓글 원문은 기본 닫힌 네이티브 `<details class="timeline-disclosure">` 안에 보관한다. 「전체 타임라인 보기」를 눌러 펼치며 기본 화면에 긴 원문을 노출하지 않는다. 닫혀 있어도 원문 전체 복사는 유지한다.
- 공통 하단에 실제 읽은 화면 버전을 표시하고, `build-info.json`을 캐시를 우회하여 조회해 최신 배포 버전과 비교한다. 값이 다르면 「새 버전 열기」로 네트워크 우선 이동한다.
- 버전 변경 시 `assets/site.js`와 `build-info.json`을 동시 갱신한다. 원문·근거·시간표는 수정하지 않는다.

- 홈의 주 행동은 대표 강의 읽기와 자료 검색·탐색, 보조 동작은 미니강좌 이동이다. 계정·학습 기록 UI는 두지 않는다.
- 반응형 버튼은 최소 44px 터치 영역과 명확한 계층을 유지하고 모바일 화면에서 중복 진입 링크를 추가하지 않는다.

## 7. 내면의 서재 — 브랜드 및 에디토리얼 디자인 (2026-11-01)

- **브랜드 이름:** 내면의 서재. 기존 ‘내면을 공부하는 시간’은 짧고 기억하기 쉬운 학습 공간의 이름으로 정리한다. URL, 원본 영상 제목, 강의 내용은 변경하지 않는다.
- **브랜드 목적:** 강연·책·연구를 연결하는 개인 학습 공간. 대중 홍보형 소개보다 읽기·요약·개념 연결·복습에 초점을 둔다. 홈 H1은 ‘학습 자료’, 화면 타이틀은 ‘내면의 서재 · 페이지 이름’.
- **시각 언어:** 크림 종이색과 깊은 녹색을 유지하고, 작은 책 아이콘·왼쪽 정렬·뚜렷한 제목 위계·낮은 채도의 카드·넉넉하지만 과하지 않은 여백을 사용한다. 기본 글꼴은 시스템 글꼴로 유지하여 별도 웹폰트 다운로드를 요구하지 않는다.
- **보조 토큰:** `--brand-ink:#213b30`, `--brand-soft:#edf2e9`, `--brand-outline:#dbe5da`, `--reading-measure:720px`, `--card-shadow:0 2px 12px rgba(32,55,43,.035)`. 기존 핵심 토큰의 값은 그대로 사용한다.
- **소스 및 배포:** 이름·서브타이틀은 `scripts/build_library.py`의 상수를 따른다. **배포·정적 자산·서비스 워커 버전의 단일 원본은 `build-info.json.version`**이며 생성기는 이 값을 읽는다. 새 페이지 제작/리브랜딩 때 원고 생성기와 모든 생성 HTML을 일치시킨다. 버전을 여러 JS·Python 파일에 반복 하드코딩하지 않는다. 별도 수동 페이지(`concepts.html`)도 동일하게 적용한다.
- **검증:** `tests/test_editorial_brand.py`에서 전체 페이지 제목·로고·공통 자원을, Playwright에서 360/390/1280px의 시각적 위계·가로 넘침·검색·로그인·타임라인·복사를 검사한다. 실제 iPhone Safari 확인과 자동 Chromium 검사는 구분한다.

- 홈의 주요 행동은 강의 고르기와 미니강좌 두 개로 제한한다. 계정 관리는 콘텐츠 탐색의 중심이 아니므로 **푸터에서만** 작은 보조 버튼으로 노출한다.

## 9. 확장 가능한 학습 서재 (2026-11-02)
- 홈은 특정 교수의 전용 소개가 아닌 강연자·저자와 무관한 개인 학습 공간. 실제 게시된 자료만 목록에 보여준다.
- 모든 자료 카드는 동일한 디자인 토큰을 쓰며 `creator`를 표시한다. 검색에는 제목·설명·강연자·저자·태그를 포함한다.

## 홈 탐색 상태 보존 (2026-11-02)
- 홈 검색은 `q` 주소 매개변수로 복원하며 검색 입력/주제 선택/초기화 시 같은 이력을 갱신한다. 읽기 화면에서 뒤로 돌아오거나 새로고침해도 검색어·결과·선택 칩이 일치해야 한다. 다른 주소 매개변수와 앵커는 보존한다.
- 검색 초기화는 결과 0개일 때도 제공하고 검색 입력란으로 포커스를 돌려준다. 키보드로 선택한 주제 버튼의 포커스를 임의로 제거하지 않는다.
- 목록 첫 항목은 편집 순서의 대표 강의다. 공개일을 정리일처럼 표시하거나 실제 정리일 근거 없이 ‘최근 정리’라고 표시하지 않는다.

## 간단한 학습 상태 버튼
- 로그인 전에는 짧은 로그인 링크만 노출한다. 이력과 계정으로 가는 중복 버튼을 강의 상단에 추가하지 않는다.

## 강의 요약의 화면 언어와 제목 위계 (2026-11-02)
- 독자에게 내부 구성 방식인 ‘3단 요약’을 노출하지 않고 **‘핵심 요약’**으로 표시한다. 한 문장 → 핵심 3가지 → 접힌 5분 요약의 구성은 유지한다.
- 모바일 본문에서 강의 제목(h1) → 핵심 요약(h2) → 소제목(h3) → 본문 순서로 글꼴 크기와 굵기를 분명히 구분한다. **소제목이 본문보다 과도하게 크지 않게** 하고, 본문은 15–16px·행간 약 1.7을 기준으로 한다.

## 공개 학습 기록 기능 제거 (2026-11-02 · 현행 우선 규칙)
- 스터디 앱은 **로그인 없는 읽기 전용 학습 자료 사이트**로 운영한다. 상단 메뉴는 자료 모음 / 용어와 개념 두 가지다.
- 강의·미니강좌·5분 요약과 댓글 복사, 검색·필터, 화면 버전 안내는 보존한다. **완료·복습 체크, 개인 기록, 진행 상태, 이력 목록, 로그인·계정 UI 및 클라우드 기록 읽기/쓰기 코드를 재도입하지 않는다.**
- `study-history.html`, `assets/progress.js`, `assets/account.js`, `assets/firebase.js`, `assets/firebase-config.js`는 배포 트리에서 제거한다. 서비스 워커에서도 이력 주소를 사전 캐시하지 않는다.
- 기존 원격 Firebase 서버의 데이터는 사이트 코드 제거와 별개이다. **서버의 기록을 자동 삭제했다고 주장하지 않는다.** 데이터의 완전 삭제는 별도 접근 권한과 절차가 필요하다.
- 새로운 강의를 추가할 때 별도 학습 기록 위젯이나 Firebase 저장 기능을 만들지 않는다. 테스트는 기능 부재와 학습 자료의 검색·읽기·댓글 복사 유지 여부를 검사한다.

## 레이아웃 정교화 (2026-11-02)
- 헤더의 실제 전역 메뉴는 **자료 모음·용어와 개념의 2개**이다. 모바일에서는 2등분 그리드로 배치해 빈 열이 생기지 않게 한다.
- 홈은 대표 자료 한 개와 자료 검색·목록을 분리하고, 모바일은 목록 1열, PC는 2열을 유지한다. 카드 제목·본문의 줄바꿈과 수평 넘침을 막는다.
- 강의·미니강좌·5분 요약은 최대 읽기 폭을 720px로 유지하고, 모바일에서는 가용 폭을 사용한다. h2–h3–본문 글자 위계와 절 사이의 구분선·여백을 일관되게 관리한다.
- 360px·390px·768px·1280px에서 계산된 메뉴 열 수, 각 카드 폭, 좌우 여백, 읽기 폭, 가로 스크롤 발생 여부를 검증한다. 과도한 추가 장식은 금지한다.

## iPhone 홈 화면 PWA · PC 브라우저 호환 (2026-11-02)
- PC는 설치 유도 없는 일반 브라우저/즐겨찾기 사용, iPhone은 Safari '홈 화면에 추가'로 독립 창 실행. 두 플랫폼에 **동일한** 공개 콘텐츠와 네비게이션을 제공한다.
- 헤더에 공통 테마 버튼을 배치해 **시스템 자동 → 라이트 → 다크** 순서로 전환한다. 자동은 `prefers-color-scheme` 미디어 쿼리를 따라가며 선택한 테마만 브라우저 로컬 저장소에 보존한다.
- 다크 팔레트는 기존 토큰을 덮어쓰고 본문 대비·버튼 대비·입력창·카드·접기 화면을 확인한다. 재사용 가능한 색상 토큰으로 관리하고 인라인 스타일을 만들지 않는다.
- `manifest.webmanifest`의 경로는 GitHub Pages 프로젝트 범위에 묶는다. `viewport-fit=cover`와 `env(safe-area-inset-*)`로 홈 화면 실행 시 노치를 피한다.

## 미니멀 모던 디자인 (2026-11-06 · 시각 언어 현행 우선 규칙)
- 이 절은 7절의 ‘크림 종이색과 깊은 녹색’ 시각 언어를 대체한다. 구조·내비게이션·기능·앵커는 바꾸지 않고 색, 면, 경계선, 타이포그래피만 바꾼다.
- **색:** 흰 배경(--paper, --surface), 거의 검은 글자(--ink #18181b), 회색 보조 글자(--muted #6b6b73), 얇은 경계선(--line #e7e7ea). 강조색은 하나(--green #2c6a4c)로 링크와 작은 라벨에만 쓴다. 주 버튼과 선택된 칩은 --ink 바탕에 --paper 글자.
- **면:** 카드는 기본 상태에서 1px 경계선만 쓰고 그림자(--card-shadow: none)를 쓰지 않는다. 호버 때의 이동·그림자는 아래 ‘인터랙티브 스타일’ 절의 규칙만 따른다. 모서리는 --radius 12px, 컨트롤 8px, 칩 999px, 태그 6px.
- **헤더·내비게이션:** 흰 바탕에 아래 1px 선. 현재 메뉴는 배경 대신 아래 2px 밑줄로 표시한다. 모바일 2열 메뉴와 44px 터치 영역은 유지한다.
- **핵심 요약 한 문장:** 배경 상자 없이 왼쪽 2px 세로선으로 구분한다.
- **다크 모드:** 중성 검정 계열(#0b0b0c 배경, #111113 면, #f4f4f5 글자)과 밝은 녹색 강조(#86d9ae). 라이트와 같은 구조를 쓰며 선택 칩·주 버튼은 --ink/--paper 반전으로 동작한다.
- **글꼴:** 시스템 글꼴 유지(웹폰트 없음). 본문 16px·행간 1.8, 제목은 굵기 650–700과 음수 자간.
- 구현 위치는 assets/site.css 최종 ‘Minimal modern / v8’ 레이어와 :root 토큰이다. 검사 기준은 scripts/validate_design_system.py의 TOKENS이다. 브라우저 상단 색(theme-color)은 라이트 #ffffff, 다크 #0b0b0c이다.

## 인터랙티브 스타일 (2026-11-06 · 미니멀 모던 위의 동작 규칙)
- 이 절은 미니멀 모던 절의 정적 규칙에 동작을 더한다. 색·구조·기능은 바꾸지 않는다.
- **호버(마우스 환경만):** 카드·대표 강의는 3px 위로 이동하고 경계선이 --ink로 바뀌며 얕은 그림자가 생긴다. 제목은 --green으로 바뀐다. 모든 호버 효과는 `@media(hover:hover) and (pointer:fine)` 안에 둔다. 터치 기기에는 호버 이동을 주지 않는다.
- **눌림:** 버튼·칩은 scale(.97), 카드는 scale(.99). 전환은 .16초, 곡선은 --ease-out.
- **등장:** 홈·목록·강의 섹션은 .4–.5초 동안 아래에서 10px 올라오며 나타난다. 카드는 최대 .25초까지 순차 지연한다. 애니메이션 fill-mode는 `backwards`만 쓴다(`both`·`forwards`는 호버 이동을 덮어쓰므로 금지).
- **접기 열림:** details를 펼치면 내용이 4px 아래에서 나타난다.
- **읽기 진행 막대:** 강의·5분 요약·미니강좌에서 상단에 3px 막대(`.read-progress`)가 스크롤 비율만큼 --green으로 채워진다. 장식 요소이며 aria-hidden, 상태 저장·계정 기능은 없다. 인쇄에서는 숨긴다.
- 진행 막대는 `animation-timeline: scroll()`을 지원하는 브라우저에서 스크롤에 직접 연동해 끊김 없이 그리고, 미지원 브라우저는 JS 값(--p)에 .14초 선형 보간을 적용한다.
- **모션 줄이기:** `prefers-reduced-motion: reduce`에서는 모든 애니메이션·전환·호버 이동을 끈다.
- 애니메이션은 transform과 opacity만 쓴다. 레이아웃 속성(width, height, top 등)을 애니메이션하지 않는다.
