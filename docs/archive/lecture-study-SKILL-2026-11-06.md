# 강의 학습 페이지 편집 스킬

> **현행 구성 (2026-11-06, 이 문서의 이전 설명보다 우선):** 공개 화면은 홈(강의 목록)과 강의 페이지뿐이며, 강의 페이지는 핵심 요약(한 문장·핵심 세 가지)과 타임스탬프만 둔다. 5분 요약·미니강좌·용어와 개념은 게시하지 않고 원고 데이터만 보존한다. 자세한 기준은 AGENTS.md ‘현행 구성’과 docs/design-system.md ‘블랙·레드·그레이 / v10’.

## 반드시 읽을 자료
디자인과 화면 수정 전에는 [디자인 기준](../../../docs/design-system.md)을 먼저 읽는다. 이 파일의 과거 마인드맵·상세 섹션 필수 지침보다 마지막 '현재 강의 구성'의 3단 요약·미니강좌 분리를 우선한다.
`AGENTS.md`, `편집규칙.md`, `용어집.md`, 강의별 `study-audits/<영상ID>.json` 및 실제 자막·슬라이드·영상 설명란을 먼저 확인한다. 김주환 전용 운영 규칙은 다른 강사의 무관한 자막 다운로드 업무에 강제하지 않는다.

## 사이트 운영 기준
- GitHub Pages 공개 URL은 유지하되 콘텐츠와 탐색은 **소유자 개인의 공부**를 위해 작성한다. 소개·홍보·환영·방문자 튜토리얼을 만들지 않는다.
- 홈에는 최근 강의·검색·강의 목록·개념집 이동만 우선 배치한다. 공개 페이지이므로 민감한 개인 정보나 비밀을 게시하지 않는다.

## 결과물 구성

- 공통 학습 흐름: 첫 화면 중요성·학습 성과 → 요약 → 상세 해설 → 실제 원본 화면(있는 경우) → 학습 순서·실천 → 원본 타임라인. 각 페이지에서 목차 번호와 실제 섹션 순서를 일치시키고 기존 앵커·복사 기능을 보존한다.

1. **서두 소개 문단 하나:** 강의가 답하는 실제 삶의 질문·학문적 의의·흔한 오해와, 실제로 배울 개념·비교·판단 및 현실적인 적용을 라벨 없이 녹여 쓴다. 근거 없는 효과를 약속하거나 조회수·선정 이유를 끼워넣지 않는다.
2. 핵심 요약, 주제별 통합 해설, 실제 화면·영상 구간 근거, 일상 적용, 타임라인을 논리적으로 연결한다. 영상 없이도 핵심 원리를 이해할 수 있게 설명한다.
3. 전문어는 쉬운 정의와 원어를 처음에 소개한다. 강의 주장, 학술 연구 결과, 강의 밖의 [보충] 예시를 구분한다.
4. 조회수, 작업일지, 자막 추출 과정, 검수 결과, 배포 상태, 작성자의 자찬을 강의 본문에 넣지 않는다. 근거 수준·측정 범위 등 이해에 필요한 제한 사항은 해당 주장 가까이에 간결히 쓴다.
5. 제목의 반복이나 타임라인 나열로 해설을 대체하지 않는다. 본문에는 과학적 구별과 구체적 이유를 제공한다.


- 전체 공개 강의 페이지를 스캔해 자막 추출·검증·재구성·작업 이력에 대한 독자용 자기설명 문구를 제거한다. 검수의 흔적은 감사 기록에만 보존하며 과학적 내용에 필요한 근거 제한은 삭제하지 않는다.

## 원자료와 자막
- 휴버맨 강의는 원본 장편 영상만 다루고 Essentials 등 편집본은 페이지에서 제외한다. 후속 연구는 원본 강의의 근거 검증에만 활용한다.
- 출처 영상 ID와 버전을 고정하고 원본/편집본의 타임라인을 혼합하지 않는다. 실제 자막의 언어·타임코드 유무·범위를 기록한다.
- 원본 자막·이미지는 보존하고 근거를 대조한다. 시간 정보가 없는 TXT를 발화 시각의 검증 근거처럼 사용하지 않는다.
- 통계·임상·약물·보충제·인과관계 등은 주장별 근거의 수준과 측정 대상을 검토한다. 모호하면 불확실성을 명시한다.
- 댓글은 원본 챕터 시각으로 작성하고 실제 게시 여부는 계정 권한과 결과를 확인한다. 중복 댓글을 만들지 않는다.
- 댓글용 타임라인은 기존 강의와 동일하게 `■ 핵심 세션`(5개 이하, 본강의 시작 포함) → `—상세—` → `■ 번호. 제목`과 검증된 시각으로 구성한다. 강의 페이지에 `<pre>` 원문 코드블록과 `댓글 전체 복사` 버튼, 복사 결과 안내를 제공한다. 댓글 원문만 복사하고 웹의 링크·설명문은 제외한다. 채팅에서도 코드블록으로 복사 가능하게 제공한다.

## 웹과 게시 검수
- `lectures.json`을 홈 소개의 단일 원본으로 삼고 `scripts/build_library.py`로 생성한다. 생성기와 생성된 홈이 불일치하면 수정한다.
- `assets/site.css`, `assets/site.js`를 공통 사용하고 기존 이미지·검색·접기/펼치기·댓글 복사·내부 앵커를 유지한다.
- `python scripts/validate_site.py`, `python scripts/validate_study_pages.py`, `python -m unittest discover -s tests -p 'test_study_validation.py'`를 실행하고, PC·모바일의 공개 배포를 검증한다. 수행하지 못한 검사를 통과했다고 주장하지 않는다.
- 브랜치 → 검사 → PR → 병합 → 공개 웹 확인 순서로 진행한다.

## 좋은 규칙의 지속 반영
- 반복되는 결함 또는 명확한 사용자 피드백이 있으면 재발 방지를 위한 **검증 가능한 일반 원칙**을 작성한다. 실제 사례와 근거를 확인하고 기존 규칙과 모순·중복되는지 비교한다.
- 원칙이 재사용 가능하면 `편집규칙.md`에 정식 반영하고, 이 스킬에는 실행할 수 있는 짧은 체크/절차로 반영한다. 해당 작업에만 해당하는 사안은 `study-audits/`나 `docs/design-review-YYYY-MM-DD.md`에만 남긴다.
- 가능하면 누락을 잡는 자동 검사나 회귀 테스트를 추가한다. 규칙과 코드 변경은 같은 PR에서 리뷰하며, 원자료 정확성·기존 기능·권한을 훼손하는 규칙은 자동 채택하지 않는다.
- 위 기준은 앞으로 이 저장소에서 스킬을 적용해 편집할 때 실행하는 절차이며, 사용자가 요청하지 않은 백그라운드 감시·외부 스킬 수정·자동 병합을 의미하지 않는다.

## 홈의 정합성 검사와 재발 방지

1. 새 강의가 보이면 `lectures.json`에 같은 영상 ID와 학습 설명이 있는지 확인한다. 없으면 먼저 등록한다.
2. 실제 영상 공개일을 확인하지 못했다면 `date: null`로 둔다. 레지스트리 순서는 개인 학습용 노출 순서다.
3. 홈 파일을 손으로만 수정하지 않고 생성기와 레지스트리를 함께 수정해 재생성한다.
4. 등록 강의 수 = 홈 카드 수 = 검색 결과 초기 개수인지 확인하고, 모든 카드의 연결 대상과 문장 품질을 검사한다.
5. 사용자가 반복해서 발견한 문제는 사례를 검토해 규칙(품질 기준)과 스킬(실행 절차)에 나누어 반영한다. 중복·상충 검사를 하고 관련 테스트를 가능하면 추가한다.


## 원자료 복구와 검수 재발 방지

- 도구 실패 시 기존 작업 환경과 대체 경로를 확인하고 독립적으로 수행 가능한 작업을 계속한다.
- 자막 변환의 첫·마지막 발화를 원본과 대조한다. 롤링 자막 중복과 실제 발화 누락을 구분한다.
- 화면은 시각만으로 가까운 주제에 자동 배정하지 않는다. 연구·정의·실천 등 실제 내용을 대조하여 연결한다.
- 독립 검수는 실제 원고를 대상으로 수행하며 검수 범위와 한계를 기록한다.


## 한국어 문장과 검증 누락 방지

- 제목·요약·소제목을 소리 내어 읽듯 검토한다. 번역투, 추상명사 나열, 의미가 맞지 않는 서술어를 자연스러운 한국어로 고친다. 전문 개념과 근거의 한계는 보존하고 제목의 강제 줄바꿈으로 비문을 가리지 않는다.
- 제목 수정은 `lectures.json` → 생성 홈 → 강의 제목을 함께 반영한다. 확인 질문의 답이 질문의 반대 상황을 설명하지 않는지 확인한다.
- `python scripts/build_library.py --check`와 `python -m unittest discover -s tests`를 실행한다. 등록 강의와 감사 기록의 수가 맞는지 확인하고 구조 검사 통과를 원본 전체 대조 완료로 쓰지 않는다.
- 접힌 `details` 자체와 내부 앵커를 직접 열어 본다. 화면 폭·검색 복귀·목차·접기·클립보드를 실제 브라우저에서 확인하고 모바일 실기기와 PC 브라우저 반응형 검사를 구분해 보고한다.

- 본문·메타 설명·복사 문구에 자막 확보 상황, ‘소개란 없음’ 같은 제작 사족을 넣지 않는다. 필요하면 `docs/`나 `study-audits/`에 기록한다.
- 한 페이지 안에서 의미 없이 어투를 오락가락 바꾸지 않되, 안내·상태 문구는 명사구로, 설명은 자연스러운 문장으로 작성한다. ‘화면 화면’ 같은 중복 표현과 근거 없는 ‘교수의 해석’을 점검한다.
- 강의별 페이지에는 다른 강의 추천 링크를 넣지 않는다.

## 학습 탐색과 연결

- 공통 목차에는 큰 학습 단계만 두고 긴 주제 목록은 본문 안의 접을 수 있는 세부 목차로 제공한다. 기존 앵커와 해설은 보존한다.
- 개념집에서 해설이 있는 개념은 해당 개념의 정확한 본문 앵커로 연결한다. 홈의 학습 순서는 레지스트리에 있는 강의만 사용한다.
- 강의 간 학습 순서는 홈에서 제공한다. 도파민 페이지에는 다른 강의 추천을 추가하지 않는다.

## 영상 타임라인 표시

- 강의 페이지에 시각별 영상 링크를 길게 나열한 별도 타임라인 목록을 만들지 않는다. 댓글용 타임라인 원문과 복사 버튼만 유지한다. 해설·원본 화면의 개별 근거 시각 링크는 유지한다.
- 기존 목록을 제거할 때 댓글 원문과 복사 기능을 보존하고 목차의 중복 이동 항목을 정리한다. 기존 타임라인 주소는 댓글 복사 영역으로 연결한다.

## 강의 공통 레이아웃

- 모든 강의는 공통 헤더·첫 화면 버튼(핵심 요약/주제별 해설/원본 영상)·중요성과 학습 목표·목차·본문·하단 탐색·푸터를 사용한다.
- 본문의 필수 단계는 핵심 요약 → 접는 주제별 해설 → 학습 순서와 일상 적용 → 근거와 출처 → 댓글용 타임라인이다. 원본 화면은 자료가 있을 때 관련 해설에 연결한다.
- 공통 단계 ID는 lecture-overview, lecture-details, lecture-practice, lecture-sources, lecture-comment로 유지하고 기존 앵커도 보존한다. 공통 site.js에서 펼치기와 댓글 원문 복사를 처리하며 복사 상태는 role=status·aria-live=polite로 알린다.
- 강의 하단 탐색은 강의 모음과 개념집으로 통일한다. validate_site.py의 공통 레이아웃 검사와 PC·모바일 화면 검사를 통과해야 한다. 캐시된 공통 파일로 동작이 달라지지 않도록 자산 버전도 갱신한다.

## 강의 마인드맵

- 모든 강의는 핵심 요약 다음에 미니멀한 마인드맵을 제공한다. 중심 질문과 핵심 개념의 관계를 짧은 가지로 표현하고 세부 항목은 실제 해설 앵커로 연결한다. 새로운 과학적 주장이나 원본에 없는 인과관계를 만들지 않는다.
- data/lecture_mindmaps.json에서 강의별 개념 구조를 관리하고 scripts/build_mindmaps.py로 생성한다. --check와 사이트 검증으로 데이터·본문 일치와 앵커를 검사한다. PC에서는 연결선이 있는 가지 구조, 모바일에서는 가로 넘침 없는 세로 구조를 사용한다.

- 마인드맵은 중심 노드와 양 끝 가지 연결점의 중점이 일치해야 한다. 연결선은 각 가지 영역의 중앙으로 연결하고 영역 안의 제목·항목은 왼쪽으로 맞춘다. 제목 행 높이는 실제 내용에 맞춰 공유하고 고정 높이로 빈 줄을 만들지 않는다. 항목 수가 다른 강의와 PC·모바일을 함께 확인한다. 가지를 같은 높이의 박스로 감싸지 않고, 연결선과 여백만으로 구분하여 항목 수가 적은 가지에 빈 공간이 강조되지 않게 한다.

## 자연스러운 한국어 편집

- 모든 문장을 한다체로 강제하지 않는다. 화면 목적에 따라 제목·명사구·상태명과 완결문을 유연하게 사용한다.
- 용어 정의는 핵심 뜻과 구별을 먼저 제시하고, 개념상 필요한 한계 설명은 자연스러운 문장으로 유지한다. 명사형 종결만 기계적으로 반복하지 않는다.
- 5분 요약·미니강좌는 원고의 과학적 정확성, 논지, 흐름을 보존한다. ‘~다’ 금지 규칙도, ‘~다’ 강제 규칙도 만들지 않는다.
- 화면 문구를 수정할 때 실제 모바일 가독성과 중복 어미를 사람의 편집 기준으로 읽고, 대표적인 재발 사례를 회귀 테스트로 등록한다. 원문 인용·타임라인·기존 데이터 값은 보존한다.


- 기존 기록 조회에 실패하면 입력·저장을 제공하지 않고 다시 불러오기를 제공합니다. 진행 상태·메모·변경 이력은 하나의 원자적 배치로 저장합니다.
- 계정 전환 시 기존 화면을 즉시 비우고, 요청을 시작한 계정의 세대 번호가 현재와 같을 때만 조회·저장 결과를 화면에 반영합니다. 지연 응답·부분 실패는 회귀 검사로 확인합니다.


- 모바일 입력란의 실제 계산 글자 크기는 16px 이상으로 유지합니다. 축소한 카드의 font:inherit 또는 뒤쪽 font 단축 속성이 이를 덮어쓰지 않는지 확인합니다. 확대 방지를 위해 사용자 확대 기능을 차단하지 않습니다.


## 읽기 화면 디자인 검수

- 고정 헤더·목차의 위치와 앵커 여백은 실제 요소 높이를 기준으로 계산한다. 메뉴 줄바꿈·확대·모바일 회전 후에도 목차가 헤더 아래에 보여야 한다.
- 해설은 주제당 한 겹의 시각적 컨테이너만 사용한다. 내부 개념·질문·화면은 소제목·간격·구분선으로 나누고 배경·테두리·들여쓰기를 중첩하지 않는다.
- 홈 검색은 별도 외곽 카드 없이 제공하고 모바일 주제 칩은 가로 탐색한다. 선택 상태는 aria-pressed로 표시한다. 본문·보조 동작은 보통 굵기, 주제 제목은 진하게 구분하며 44px 터치 영역과 입력란 16px를 유지한다.
- 분량 기준: 강의 페이지 본문(`<main>` 텍스트)은 대략 6,000~13,000자로 유지한다. 별도 복습 질문 섹션, "상황·장면으로 이해하기"·"오해하지 않기"·"헷갈리지 않기" 같은 반복 블록, 화면별 해설 문단, 앞 내용을 되풀이하는 "돌아와 확인" 화면은 만들지 않는다. 주제마다 핵심 문단 1~2개와 확인 질문·답으로 쓴다.


## 현재 강의 구성 (2026-10-31 사용자 요청, 이전 레이아웃 기준에 우선)
- 각 강의 본문은 3단 요약(한 문장 → 핵심 세 가지 → 접는 5분 요약)과 댓글용 타임라인으로 구성한다. 마인드맵·슬라이드 갤러리·별도 해설·실천 섹션은 본문에서 제외한다. 원자료 파일과 출처·기록은 보존한다.
- 미니강좌는 `data/mini_courses.json`에서 작성하고 `scripts/build_compact_lectures.py`로 별도 `mini-courses/`에 생성한다. 원강의에 기초한 재구성임을 짧게 밝히며 새 예시는 [보충]으로 구분한다.
- 한 문장·세 가지 핵심·미니강좌를 같은 원고에서 생성한다. 기존 5분 요약은 `data/summaries.json`, 타임라인과 기존 앵커는 `data/lecture_compact.json`에 보존한다.
- 기존 세부 앵커는 펼칠 수 있는 5분 요약 안에 유지한다. 기존 분량·문답·이미지 수·마인드맵 강제 검사는 compact 레이아웃에 적용하지 않고, 재생성 일치·타임라인 동일성·링크·출처·모바일 가독성을 검사한다.

## 홈 탐색 상태 보존 (2026-11-02)

- 목록 첫 항목은 편집 순서의 대표 강의다. 공개일을 정리일처럼 표시하거나 실제 정리일 근거 없이 ‘최근 정리’라고 표시하지 않는다.

## 자막 수집 도구 제한 (2026-11-02)
- **vidIQ(비디오아이큐)는 사용하지 않는다.** 자막 조회·다운로드·영상 검색·요약 및 후속 자동화에서 vidIQ 앱·API·연결 도구 호출을 금지한다. 크레딧 갱신 뒤에도 자동 재사용하지 않는다.
- 자막 확보는 사용자 제공 SRT/VTT → YouTube 공식 자막/동영상 설명란 → 허용되는 자막 다운로드 도구(yt-dlp 등) → 공개 자막 대체 경로 순으로 시도하고, 확보 실패 시 중복 재시도보다 실패 사유·대체 경로를 기록한다.
- 자막만 있고 영상 ID가 없는 경우, 제목·게시일·영상 ID를 별도로 교차 확인한다. 검증하지 않은 11자리 ID와 원본 영상 URL을 만들어 넣지 않는다. 학습 노트는 먼저 게시할 수 있으나 원본 연결 미검증 상태임을 출처 기록에 명시한다.

## 홈 대표 자료와 중복 방지 (2026-11-02)
- 브랜드 이름은 헤더에만 표시한다. 본문은 ‘학습 자료’ 한 개의 제목, 클릭 가능한 대표 자료 카드, 검색과 일반 목록으로 구성한다.
- 대표 자료는 일반 목록에 중복 노출하지 않고, 검색·필터·자료 수 집계에는 포함한다. 대표 강의 카드는 요약 앵커가 아닌 실제 강의 본문 HTML로 직접 연결한다.
- 책·연구 등 다른 종류가 대표로 선정돼도 동일 규칙으로 한 개만 표시한다. 생성기와 검색 회귀 테스트에서 중복과 링크를 검사한다.

## 한 문장 요약의 핵심 결론 기준 (2026-11-02)
- 한 문장 요약은 주제 소개나 사전적 정의가 아니라, **강의를 듣고 나서 남겨야 할 하나의 구체적인 판단 기준 또는 행동 변화**를 말한다. 제목을 읽은 사람에게도 새로운 정보가 있어야 한다.
- 원고의 **핵심 논지 → 혼동하기 쉬운 구분 → 실제로 무엇을 달리 볼지·할지**를 확인하고, 가장 중요한 메시지 하나만 남긴다. 세 요소를 기계적으로 모두 넣거나 'A가 아니라 B' 문형을 매번 반복하지 않는다.
- ‘중요하다’, ‘관여한다’, ‘과정이다’, ‘살펴야 한다’만으로 마무리하지 않는다. **왜 중요한지, 무엇과 무엇을 구분할지, 구체적으로 무엇을 살펴야 하는지**를 문장 안에 밝힌다.
- 사실과 강사의 해석 및 연구의 한계를 구분한다. 검증되지 않은 인과·치료 효과·만능 실천법을 결론으로 만들지 않는다. 논문의 조건부 결과는 ‘도움이 될 수 있다’처럼 정확한 수준으로 쓴다.
- 한 문장은 가능하면 60–120자 정도로, 쉼표를 줄이고 자연스러운 완결문으로 쓴다. 단어 수나 문형에 매이지 않는다. 소리 내어 읽어 뜻이 바로 이해되는지, ‘그래서 무엇을 기억하고 달리할까?’에 답하는지 검수한다.
- 구조 검사(문장 수, 길이, 생성 파일 정합성)는 자동화하되 **의미 있는 키 테이크어웨이인지는 사람이 원고에 근거해 최종 판단**한다.

## 공개 학습 기록 기능 제거 (2026-11-02 · 현행 우선 규칙)
- 스터디 앱은 **로그인 없는 읽기 전용 학습 자료 사이트**로 운영한다. 상단 메뉴는 자료 모음 / 용어와 개념 두 가지다.
- 강의·미니강좌·5분 요약과 댓글 복사, 검색·필터, 화면 버전 안내는 보존한다. **완료·복습 체크, 개인 기록, 진행 상태, 이력 목록, 로그인·계정 UI 및 클라우드 기록 읽기/쓰기 코드를 재도입하지 않는다.**
- `study-history.html`, `assets/progress.js`, `assets/account.js`, `assets/firebase.js`, `assets/firebase-config.js`는 배포 트리에서 제거한다. 서비스 워커에서도 이력 주소를 사전 캐시하지 않는다.
- 기존 원격 Firebase 서버의 데이터는 사이트 코드 제거와 별개이다. **서버의 기록을 자동 삭제했다고 주장하지 않는다.** 데이터의 완전 삭제는 별도 접근 권한과 절차가 필요하다.
- 새로운 강의를 추가할 때 별도 학습 기록 위젯이나 Firebase 저장 기능을 만들지 않는다. 테스트는 기능 부재와 학습 자료의 검색·읽기·댓글 복사 유지 여부를 검사한다.
