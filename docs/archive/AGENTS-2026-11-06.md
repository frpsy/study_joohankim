## 모바일 성능·캐시 회귀 방지
- CSS에서 모바일 헤더는 불투명해야 하며, 카드의 하단 링크가 `margin-top:auto`로 과도한 빈 공간을 만들지 않게 한다. `tests/browser-smoke.spec.cjs`의 iPhone 화면·오프라인 탭 이동 검사를 유지한다.
- 정적 페이지·CSS·JS를 수정할 때는 `sw.js`의 캐시 무효화 및 백그라운드 갱신 결과를 점검한다. 즉시 반영이 필요한 공통 자원 구조 변경은 `VERSION`을 갱신하고 모든 페이지에서 구버전 동작을 확인한다. 첫 방문은 여전히 네트워크 의존적임을 구분한다.
- 실제 5G/Safari 네트워크 지연을 측정하지 않았다면 개선 비율이나 밀리초 수치를 만들어 보고하지 않는다. 상세 근거는 `docs/navigation-performance-2026-11-01.md`에 정리한다.

## 화면 버전 확인 및 갱신
- 모든 페이지 하단의 `화면 v...`는 실제 로딩된 `assets/site.js`의 `CLIENT_VERSION`이다. `build-info.json`을 `cache:'no-store'`로 별도 읽어 현재 배포 버전과 비교한다. 다르면 `새 버전 열기` 링크를 제공한다.
- 사용자에게 보이는 UI 수정 시 `assets/site.js`의 `CLIENT_VERSION`과 `build-info.json.version`을 반드시 같은 새 값으로 갱신한다. 캐시 구조가 바뀌면 `sw.js VERSION`도 함께 갱신한다.
- `tests/browser-smoke.spec.cjs`에서 실제 버전 표시, 최신 확인, 구버전 발견 시 새로고침 링크를 검증한다. 버전은 최종 GitHub Actions 배포 성공과 별개이며 화면에 표시됐다는 이유만으로 배포 성공을 단정하지 않는다.

- 댓글 타임라인은 실제 원문의 맨 앞 3줄만 별도 미리보기로 기본 표시한다. 전체 원문은 닫힌 details 안에 두며 복사 버튼은 열림 여부와 관계없이 전체 원문을 복사한다.
- 버전은 2026.11.01.5로 갱신한다.

- Google Auth SDK는 버튼을 누르기 전에 준비하며, 실제 `signInWithPopup()`은 사용자 클릭 핸들러에서 어떤 비동기 `await`도 거치지 않고 직접 실행한다. 모바일 Safari에서 사용자 동작과 팝업의 연결이 끊어지지 않게 한다.
- 인증 초기화가 지연되거나 실패하면 영구 비활성 버튼을 남기지 않고 재시도 안내를 노출한다. 팝업 차단·허용 도메인 오류·연결 실패를 구분한다. 실제 Google 계정 로그인 성공은 모의 테스트만으로 보장하지 않는다.
- 수정할 때 `tests/test_record_ui.cjs`의 동기 호출 및 계정 변경 테스트, `tests/browser-smoke.spec.cjs`의 모바일 배치·버튼 전환 테스트와 전체 사이트 검사를 실행한다.

## 내면의 서재: 강연자와 자료 유형 독립성 (2026-11-02)
- 브랜드 「내면의 서재」는 강연, 책, 논문, 글과 개인 학습 노트를 연결하는 **개인 학습 공간**이다. 특정 교수의 전용 사이트로 소개하지 않는다.
- 책·논문·글·개인 노트는 `materials.json`에 `kind: book|paper|article|note`, `creator`, `title`, `description`, `tags`, 내부 `url`로 등록한다. 존재하지 않는 자료는 노출하지 않는다.
- 영상 자막·댓글용 타임라인 등 출처별 규칙은 강의에만 적용한다. 다른 출처의 자료에 김주환 교수 특화 규칙을 강제하지 않는다. 자세한 작성/검증 규칙은 `docs/content-model.md`.

## 모든 강의 요약의 한국어 문장 검사 (2026-11-02)
- 한 문장 요약은 정확히 하나의 완결된 문장으로 작성한다. ‘…신경조절물질.’ 같은 명사구 종결이나 ‘…아니다. …과정.’의 억지 두 문장 분할을 금지한다.
- 모든 등록 강의의 `data/mini_courses.json` `lead`와 실제 강의·미니강좌 HTML을 대조한다. 5분 요약 도입과 본문도 함께 독해하고, 기존 출처/연구 근거를 보존한다.
- `tests/test_korean_leads.py`와 기존 생성기 검사를 반드시 통과한다. 소제목/목록처럼 명사구가 자연스러운 곳은 서술어를 강제로 붙이지 않는다.
- 유사 문제가 재발하면 편집규칙.md의 ‘한 문장 요약의 문장 완결성’ 절을 기준으로 전체 강의에 같은 검사 범위를 적용한다.

## 학습 상태 버튼 (2026-11-02, 이전 접기 UI 기준보다 우선)
- 저장 성공 후에만 완료 표시를 변경한다. 저장 중 두 버튼을 잠그고 실패하면 기존 상태로 재시도할 수 있게 한다. 선택한 필드만 merge하며 상태와 이력은 원자적 배치로 저장한다.
- 조회 실패 시 상태 변경 버튼을 노출하지 않고 다시 불러오기를 제공한다. 계정 전환·로그아웃 시 이전 계정의 지연 응답은 무시한다. 기존 notes 문서는 삭제하지 않는다.

## 자막 수집 도구 제한 (2026-11-02)
- **vidIQ(비디오아이큐)는 사용하지 않는다.** 자막 조회·다운로드·영상 검색·요약 및 후속 자동화에서 vidIQ 앱·API·연결 도구 호출을 금지한다. 크레딧 갱신 뒤에도 자동 재사용하지 않는다.
- 자막 확보는 사용자 제공 SRT/VTT → YouTube 공식 자막/동영상 설명란 → 허용되는 자막 다운로드 도구(yt-dlp 등) → 공개 자막 대체 경로 순으로 시도하고, 확보 실패 시 중복 재시도보다 실패 사유·대체 경로를 기록한다.
- 자막만 있고 영상 ID가 없는 경우, 제목·게시일·영상 ID를 별도로 교차 확인한다. 검증하지 않은 11자리 ID와 원본 영상 URL을 만들어 넣지 않는다. 학습 노트는 먼저 게시할 수 있으나 원본 연결 미검증 상태임을 출처 기록에 명시한다.

## 홈 대표 자료와 중복 방지 (2026-11-02)
- 브랜드 이름은 헤더에만 표시한다. 본문은 ‘학습 자료’ 한 개의 제목, 클릭 가능한 대표 자료 카드, 검색과 일반 목록으로 구성한다.
- 대표 자료는 일반 목록에 중복 노출하지 않고, 검색·필터·자료 수 집계에는 포함한다. 대표 강의 카드는 요약 앵커가 아닌 실제 강의 본문 HTML로 직접 연결한다.
- 책·연구 등 다른 종류가 대표로 선정돼도 동일 규칙으로 한 개만 표시한다. 생성기와 검색 회귀 테스트에서 중복과 링크를 검사한다.

## 한 문장 요약의 핵심 결론 기준 (2026-11-02)
- 한 문장 요약은 주제 소개나 사전적 정의가 아니라, **강의를 듣고 나서 남겨야 할 하나의 구체적인 판단 기준 또는 행동 변화**를 말한다. 제목을 읽은 사람에게도 새로운 정보가 있어야 한다.
- 원고의 **핵심 논지 → 혼동하기 쉬운 구분 → 실제로 무엇을 달리 볼지·할지**를 확인하고, 가장 중요한 메시지 하나만 남긴다. 세 요소를 기계적으로 모두 넣거나 'A가 아니라 B' 문형을 매번 반복하지 않는다.
- ‘중요하다’, ‘관여한다’, ‘과정이다’, ‘살펴야 한다’만으로 마무리하지 않는다. **왜 중요한지, 무엇과 무엇을 구분할지, 구체적으로 무엇을 살펴야 하는지**를 문장 안에 밝힌다.
- 사실과 강사의 해석 및 연구의 한계를 구분한다. 검증되지 않은 인과·치료 효과·만능 실천법을 결론으로 만들지 않는다. 논문의 조건부 결과는 ‘도움이 될 수 있다’처럼 정확한 수준으로 쓴다.
- 한 문장은 가능하면 60–120자 정도로, 쉼표를 줄이고 자연스러운 완결문으로 쓴다. 단어 수나 문형에 매이지 않는다. 소리 내어 읽어 뜻이 바로 이해되는지, ‘그래서 무엇을 기억하고 달리할까?’에 답하는지 검수한다.
- 구조 검사(문장 수, 길이, 생성 파일 정합성)는 자동화하되 **의미 있는 키 테이크어웨이인지는 사람이 원고에 근거해 최종 판단**한다.

## 학습 페이지 요약 레이블 (2026-11-02)
- 공개 UI에서는 ‘3단 요약’ 대신 ‘핵심 요약’을 쓴다. 내부 3단 구조(한 문장, 핵심 3가지, 5분 요약)는 그대로 유지한다.
- 모바일 강의의 h2는 약 23px, h3는 약 16px, 번호 본문은 15px을 기준으로 제목 위계를 만들고 긴 글의 줄바꿈·줄간격·들여쓰기를 점검한다.

## 공개 학습 기록 기능 제거 (2026-11-02 · 현행 우선 규칙)
- 스터디 앱은 **로그인 없는 읽기 전용 학습 자료 사이트**로 운영한다. 상단 메뉴는 자료 모음 / 용어와 개념 두 가지다.
- 강의·미니강좌·5분 요약과 댓글 복사, 검색·필터, 화면 버전 안내는 보존한다. **완료·복습 체크, 개인 기록, 진행 상태, 이력 목록, 로그인·계정 UI 및 클라우드 기록 읽기/쓰기 코드를 재도입하지 않는다.**
- `study-history.html`, `assets/progress.js`, `assets/account.js`, `assets/firebase.js`, `assets/firebase-config.js`는 배포 트리에서 제거한다. 서비스 워커에서도 이력 주소를 사전 캐시하지 않는다.
- 기존 원격 Firebase 서버의 데이터는 사이트 코드 제거와 별개이다. **서버의 기록을 자동 삭제했다고 주장하지 않는다.** 데이터의 완전 삭제는 별도 접근 권한과 절차가 필요하다.
- 새로운 강의를 추가할 때 별도 학습 기록 위젯이나 Firebase 저장 기능을 만들지 않는다. 테스트는 기능 부재와 학습 자료의 검색·읽기·댓글 복사 유지 여부를 검사한다.

## 리팩토링 이후 생성 원칙 (2026-11-02)
- **한 문장 핵심의 원본은 `data/mini_courses.json`의 `lead` 하나다.** `data/summaries.json`에 복제하지 않고 `scripts/content_registry.py`를 통해 생성기에 결합한다. 이전의 `data/summary_editorial_edits.json`, `scripts/editorial_copy.py` 덮어쓰기 체계는 재도입하지 않는다.
- 정적 페이지와 서비스 워커 버전은 `build-info.json.version`을 기준으로 생성한다. `assets/site.js`는 실제 로딩된 URL의 버전을 표시하고 `sw.js`의 캐시 이름도 등록 URL의 버전을 사용한다.
- 생성된 HTML을 손으로 수정하지 않는다. 데이터를 수정하고 생성기·원본 정합성·브라우저 회귀 테스트를 실행한다.

- 원본 자막은 항상 `transcripts/`에 가공 없이 저장해 두고, 사용자가 질문하면 그 파일에서 해당 구간을 찾아 시각과 함께 인용해 답한다. 상세는 편집규칙.md 12절.
