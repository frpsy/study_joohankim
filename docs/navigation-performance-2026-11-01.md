# 모바일 탭 전환·읽기 레이아웃 성능 개선 (2026-11-01)

## 원인 점검
- `강의 모음 / 용어와 개념 / 학습 이력`은 각각 전체 HTML 문서로 이동한다. 기존에는 사이트 자체의 공개 페이지 재방문 캐시·사전 준비가 없었다.
- 기존 `assets/firebase.js`는 인증이 필요한지와 관계없이 Auth, Firestore, App SDK를 한꺼번에 내려받았다. 홈의 계정 관리와 강의별 기록은 탐색 자체에 필요하지 않다.
- CSS 모바일 헤더에는 반투명 배경과 여러 차례 덮어쓴 반응형 규칙이 있었다. 스크롤 시 아래 텍스트가 비치고 헤더가 두꺼워 보이는 문제가 발생할 수 있다.
- 강의 목록 카드는 flex 링크의 `margin-top:auto`와 넓은 줄높이·여백 때문에 좁은 화면에서 간격이 부자연스러웠다.

## 적용한 개선
1. **정적 탭 캐시:** `sw.js`는 최초 설치 시 홈·용어집·학습 이력과 공통 CSS/JS를 미리 준비한다. 이후 동일 출처의 공개 페이지는 캐시로 우선 보여 주고 뒤에서 새 파일을 확인한다. 명시적 새로고침은 네트워크를 우선한다. 인증 API, Firestore, gstatic 같은 외부 출처는 캐시하지 않는다.
2. **Firebase 다운로드 분리:** `assets/firebase.js`에서 인증과 Firestore 다운로드를 분리하고 실패한 요청을 재시도할 수 있게 정리했다. 홈은 초기 렌더 후/설정 열 때 인증을 준비하고, 강의 기록은 로그인 후에만 Firestore를 읽는다. 학습 이력은 데이터 수집이 필요한 경우에만 Firestore를 읽는다.
3. **모바일 읽기 리듬:** 헤더는 불투명한 2행 구성으로 정리하고, 세 메뉴의 터치 영역을 유지하면서 높이를 제한했다. 카드 제목·설명·태그·링크 사이의 세로 간격을 통일하고 빈 공간을 줄였다. 본문 폭을 좁히던 이중 패딩을 바로잡았다.
4. **검증:** Chromium 360/390/1280px 렌더링·댓글 복사 회귀, 카드 높이/헤더 배경 검사, 네트워크를 끊은 뒤 홈↔개념↔이력 캐시 이동을 테스트한다.

## 데이터·보안·신선도 기준
- 사용자의 학습 기록은 원래 Firestore 규칙에 따라 온라인 인증 후 내려받는다. Service Worker에는 사용자의 로그인 정보·이력·메모를 저장하지 않는다.
- 기본 탐색에 쓰는 공개 HTML만 캐시에 남는다. 갱신된 페이지는 방문 후 백그라운드에서 내려받고 다음 이동에 반영될 수 있다. 강제로 최신 문서를 받아야 할 때는 새로고침한다.
- `sw.js`의 캐시 버전은 큰 공통 자원 변경이나 캐시 정책 변경 시 올린다. GitHub Pages의 캐시 및 브라우저 갱신 타이밍도 영향을 준다.
- 브라우저 자동 검사는 실제 iPhone Safari/5G에서의 네트워크 지연 값을 제공하지 않는다. 단축률 같은 수치를 사용하려면 해당 환경에서 비교 측정을 별도로 실시한다.
