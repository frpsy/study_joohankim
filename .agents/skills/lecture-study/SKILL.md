# 강의 학습 페이지 편집 스킬

## 반드시 읽을 자료
`AGENTS.md`, `편집규칙.md`, `용어집.md`, 강의별 `study-audits/<영상ID>.json` 및 실제 자막·슬라이드·영상 설명란을 먼저 확인한다. 김주환 전용 운영 규칙은 다른 강사의 무관한 자막 다운로드 업무에 강제하지 않는다.

## 사이트 운영 기준
- GitHub Pages 공개 URL은 유지하되 콘텐츠와 탐색은 **소유자 개인의 공부**를 위해 작성한다. 소개·홍보·환영·방문자 튜토리얼을 만들지 않는다.
- 홈에는 최근 강의·검색·강의 목록·개념집 이동만 우선 배치한다. 공개 페이지이므로 민감한 개인 정보나 비밀을 게시하지 않는다.

## 결과물 구성

- 공통 학습 흐름: 첫 화면 중요성·학습 성과 → 요약 → 상세 해설 → 실제 원본 화면(있는 경우) → 복습 질문 → 학습 순서·실천 → 원본 타임라인. 각 페이지에서 목차 번호와 실제 섹션 순서를 일치시키고 기존 앵커·복사 기능을 보존한다.

1. **첫 화면의 두 문단:** **왜 중요한가** — 강의가 답하는 실제 삶의 질문·학문적 의의·흔한 오해. **이 강의에서 얻을 수 있는 것** — 실제로 배울 개념·비교·판단과 현실적인 적용. 근거 없는 효과를 약속하거나 조회수·선정 이유를 끼워넣지 않는다.
2. 핵심 요약, 주제별 통합 해설, 실제 화면·영상 구간 근거, 복습 질문·답, 일상 적용, 타임라인을 논리적으로 연결한다. 영상 없이도 핵심 원리를 이해할 수 있게 설명한다.
3. 전문어는 쉬운 정의와 원어를 처음에 소개한다. 강의 주장, 학술 연구 결과, 강의 밖의 [보충] 예시를 구분한다.
4. 조회수, 작업일지, 자막 추출 과정, 검수 결과, 배포 상태, 작성자의 자찬을 강의 본문에 넣지 않는다. 근거 수준·측정 범위 등 이해에 필요한 제한 사항은 해당 주장 가까이에 간결히 쓴다.
5. 제목의 반복이나 타임라인 나열로 해설을 대체하지 않는다. 본문에는 과학적 구별과 구체적 이유를 제공한다.


- 전체 공개 강의 페이지를 스캔해 자막 추출·검증·재구성·작업 이력에 대한 독자용 자기설명 문구를 제거한다. 검수의 흔적은 감사 기록에만 보존하며 과학적 내용에 필요한 근거 제한은 삭제하지 않는다.

## 원자료와 자막
- 휴버맨 강의는 원본 장편 영상만 다루고 Essentials 등 편집본은 페이지에서 제외한다. 후속 연구는 원본 강의의 근거 검증에만 활용한다.
- 출처 영상 ID와 버전을 고정하고 원본/편집본의 타임라인을 혼합하지 않는다. 실제 자막의 언어·타임코드 유무·범위를 기록한다.
- 원본 자막·이미지는 보존하고 근거를 대조한다. 시간 정보가 없는 TXT를 발화 시각의 검증 근거처럼 사용하지 않는다.
- 통계·임상·약물·보충제·인과관계 등은 주장별 근거의 수준과 측정 대상을 검토한다. 모호하면 불확실성을 명시한다.
- 댓글은 원본 챕터 시각으로 작성하고 실제 게시 여부는 계정 권한과 결과를 확인한다. 중복 댓글을 만들지 않는다.
- 댓글용 타임라인은 기존 강의와 동일하게 `■ 핵심 세션`(5개 이하, 본강의 시작 포함) → `—상세—` → `■ 번호. 제목`과 검증된 시각으로 구성한다. 강의 페이지에 `<pre>` 원문 코드블록과 `댓글 전체 복사` 버튼, 복사 결과 안내를 제공한다. 댓글 원문만 복사하고 웹의 링크·설명문은 제외한다. 채팅에서도 코드블록으로 복사 가능하게 제공한다.

## 웹과 게시 검수
- `lectures.json`을 홈 소개의 단일 원본으로 삼고 `scripts/build_library.py`로 생성한다. 생성기와 생성된 홈이 불일치하면 수정한다.
- `assets/site.css`, `assets/site.js`를 공통 사용하고 기존 이미지·검색·접기/펼치기·댓글 복사·내부 앵커를 유지한다.
- `python scripts/validate_site.py`, `python scripts/validate_study_pages.py`, `python -m unittest discover -s tests -p 'test_study_validation.py'`를 실행하고, PC·모바일의 공개 배포를 검증한다. 수행하지 못한 검사를 통과했다고 주장하지 않는다.
- 브랜치 → 검사 → PR → 병합 → 공개 웹 확인 순서로 진행한다.

## 좋은 규칙의 지속 반영
- 반복되는 결함 또는 명확한 사용자 피드백이 있으면 재발 방지를 위한 **검증 가능한 일반 원칙**을 작성한다. 실제 사례와 근거를 확인하고 기존 규칙과 모순·중복되는지 비교한다.
- 원칙이 재사용 가능하면 `편집규칙.md`에 정식 반영하고, 이 스킬에는 실행할 수 있는 짧은 체크/절차로 반영한다. 해당 작업에만 해당하는 사안은 `study-audits/`나 `docs/design-review-YYYY-MM-DD.md`에만 남긴다.
- 가능하면 누락을 잡는 자동 검사나 회귀 테스트를 추가한다. 규칙과 코드 변경은 같은 PR에서 리뷰하며, 원자료 정확성·기존 기능·권한을 훼손하는 규칙은 자동 채택하지 않는다.
- 위 기준은 앞으로 이 저장소에서 스킬을 적용해 편집할 때 실행하는 절차이며, 사용자가 요청하지 않은 백그라운드 감시·외부 스킬 수정·자동 병합을 의미하지 않는다.

## 홈의 정합성 검사와 재발 방지

1. 새 강의가 보이면 `lectures.json`에 같은 영상 ID와 학습 설명이 있는지 확인한다. 없으면 먼저 등록한다.
2. 실제 영상 공개일을 확인하지 못했다면 `date: null`로 둔다. 레지스트리 순서는 개인 학습용 노출 순서다.
3. 홈 파일을 손으로만 수정하지 않고 생성기와 레지스트리를 함께 수정해 재생성한다.
4. 등록 강의 수 = 홈 카드 수 = 검색 결과 초기 개수인지 확인하고, 모든 카드의 연결 대상과 문장 품질을 검사한다.
5. 사용자가 반복해서 발견한 문제는 사례를 검토해 규칙(품질 기준)과 스킬(실행 절차)에 나누어 반영한다. 중복·상충 검사를 하고 관련 테스트를 가능하면 추가한다.


## 원자료 복구와 검수 재발 방지

- 도구 실패 시 기존 작업 환경과 대체 경로를 확인하고 독립적으로 수행 가능한 작업을 계속한다.
- 자막 변환의 첫·마지막 발화를 원본과 대조한다. 롤링 자막 중복과 실제 발화 누락을 구분한다.
- 화면은 시각만으로 가까운 주제에 자동 배정하지 않는다. 연구·정의·실천 등 실제 내용을 대조하여 연결한다.
- 독립 검수는 실제 원고를 대상으로 수행하며 검수 범위와 한계를 기록한다.


## 한국어 문장과 검증 누락 방지

- 제목·요약·소제목을 소리 내어 읽듯 검토한다. 번역투, 추상명사 나열, 의미가 맞지 않는 서술어를 자연스러운 한국어로 고친다. 전문 개념과 근거의 한계는 보존하고 제목의 강제 줄바꿈으로 비문을 가리지 않는다.
- 제목 수정은 `lectures.json` → 생성 홈 → 강의 제목을 함께 반영한다. 복습 답이 질문의 반대 상황을 설명하지 않는지 확인한다.
- `python scripts/build_library.py --check`와 `python -m unittest discover -s tests`를 실행한다. 등록 강의와 감사 기록의 수가 맞는지 확인하고 구조 검사 통과를 원본 전체 대조 완료로 쓰지 않는다.
- 접힌 `details` 자체와 내부 앵커를 직접 열어 본다. 화면 폭·검색 복귀·목차·접기·클립보드를 실제 브라우저에서 확인하고 모바일 실기기와 PC 브라우저 반응형 검사를 구분해 보고한다.

- 본문·메타 설명·복사 문구에 자막 확보 상황, ‘소개란 없음’ 같은 제작 사족을 넣지 않는다. 필요하면 `docs/`나 `study-audits/`에 기록한다.
- 한 페이지 안에서 문체를 섞지 않는다(한다체). ‘화면 화면’ 같은 중복 단어와 근거 없이 쓴 ‘교수의 해석’ 표현을 점검한다.
- 강의별 페이지에는 다른 강의 추천 링크를 넣지 않는다.

## 학습 탐색과 연결

- 공통 목차에는 큰 학습 단계만 두고 긴 주제 목록은 본문 안의 접을 수 있는 세부 목차로 제공한다. 기존 앵커와 해설은 보존한다.
- 개념집에서 해설이 있는 개념은 해당 개념의 정확한 본문 앵커로 연결한다. 홈의 학습 순서는 레지스트리에 있는 강의만 사용한다.
- 강의 간 학습 순서는 홈에서 제공한다. 도파민 페이지에는 다른 강의 추천을 추가하지 않는다.

## 영상 타임라인 표시

- 강의 페이지에 시각별 영상 링크를 길게 나열한 별도 타임라인 목록을 만들지 않는다. 댓글용 타임라인 원문과 복사 버튼만 유지한다. 해설·원본 화면의 개별 근거 시각 링크는 유지한다.
- 기존 목록을 제거할 때 댓글 원문과 복사 기능을 보존하고 목차의 중복 이동 항목을 정리한다. 기존 타임라인 주소는 댓글 복사 영역으로 연결한다.

## 강의 공통 레이아웃

- 모든 강의는 공통 헤더·첫 화면 버튼(핵심 요약/주제별 해설/원본 영상)·중요성과 학습 목표·목차·본문·하단 탐색·푸터를 사용한다.
- 본문의 필수 단계는 핵심 요약 → 접는 주제별 해설 → 복습 질문 → 학습 순서와 일상 적용 → 근거와 출처 → 댓글용 타임라인이다. 원본 화면은 자료가 있을 때 관련 해설에 연결한다.
- 공통 단계 ID는 lecture-overview, lecture-details, lecture-review, lecture-practice, lecture-sources, lecture-comment로 유지하고 기존 앵커도 보존한다. 공통 site.js에서 펼치기와 댓글 원문 복사를 처리하며 복사 상태는 role=status·aria-live=polite로 알린다.
- 강의 하단 탐색은 강의 모음과 개념집으로 통일한다. validate_site.py의 공통 레이아웃 검사와 PC·모바일 화면 검사를 통과해야 한다. 캐시된 공통 파일로 동작이 달라지지 않도록 자산 버전도 갱신한다.

## 강의 마인드맵

- 모든 강의는 핵심 요약 다음에 미니멀한 마인드맵을 제공한다. 중심 질문과 핵심 개념의 관계를 짧은 가지로 표현하고 세부 항목은 실제 해설 앵커로 연결한다. 새로운 과학적 주장이나 원본에 없는 인과관계를 만들지 않는다.
- data/lecture_mindmaps.json에서 강의별 개념 구조를 관리하고 scripts/build_mindmaps.py로 생성한다. --check와 사이트 검증으로 데이터·본문 일치와 앵커를 검사한다. PC에서는 연결선이 있는 가지 구조, 모바일에서는 가로 넘침 없는 세로 구조를 사용한다.

- 마인드맵은 중심 노드와 양 끝 가지 연결점의 중점이 일치해야 한다. 연결선은 각 가지 영역의 중앙으로 연결하고 영역 안의 제목·항목은 왼쪽으로 맞춘다. 제목 행 높이는 실제 내용에 맞춰 공유하고 고정 높이로 빈 줄을 만들지 않는다. 항목 수가 다른 강의와 PC·모바일을 함께 확인한다. 가지를 같은 높이의 박스로 감싸지 않고, 연결선과 여백만으로 구분하여 항목 수가 적은 가지에 빈 공간이 강조되지 않게 한다.

## 문체 통일: 한다체

- 인용문을 제외한 모든 완결 문장은 존대 없는 한다체로 쓴다. 홈·강의·개념집의 본문, 요약, 메타 설명, 문답의 질문과 답, 실천 안내, 복사 안내, 화면 메시지에 동일하게 적용한다.
- 설명은 ‘한다·된다·있다·없다’, 질문은 ‘무엇인가?·어떻게 구분하는가?’, 제안은 ‘살펴본다·확인한다’처럼 쓴다. 합니다체·해요체·명령형을 섞지 않는다.
- 직접 인용은 원문 어미와 의미를 보존한다. 슬라이드 제목 등 원본 화면의 문구도 같다. 따옴표 속 용어·강조·가상 예시를 직접 인용으로 취급하지 않는다.
- 제목·소제목·개념명·버튼·목차·타임라인 항목은 문장이 아닌 짧은 명사형을 사용할 수 있다. 서술문으로 작성하면 한다체를 적용한다. 원본 영상 제목과 인용된 연구·책 제목은 보존한다.
- 어미만 일괄 치환하지 않는다. 부정·가능성·시제·근거 수준을 유지하며 문장 전체를 읽고 고친다. 코드·자막 원본·URL·자료 식별자는 변경하지 않는다.
- 구호·미사여구·이용 안내 문장 없이 핵심과 근거만 쓴다(‘문구 톤’ 절). 회귀 검사는 `tests/test_site_structure.py` 가 ‘~습니다·~입니다·~합니다’ 어미를 찾는다.

## 학습 기록 오류 방지

- 기존 기록 조회에 실패하면 입력·저장을 제공하지 않고 다시 불러오기를 제공합니다. 진행 상태·메모·변경 이력은 하나의 원자적 배치로 저장합니다.
- 계정 전환 시 기존 화면을 즉시 비우고, 요청을 시작한 계정의 세대 번호가 현재와 같을 때만 조회·저장 결과를 화면에 반영합니다. 지연 응답·부분 실패는 회귀 검사로 확인합니다.

- 학습 기록은 기본적으로 접힌 한 줄 요약으로 표시합니다. 저장된 완료 상태·메모 유무만 짧게 표시하고 입력·저장은 펼쳤을 때 제공합니다. 오류가 있으면 자동으로 펼쳐 복구 안내를 표시하며 모바일 터치 영역은 유지합니다.
